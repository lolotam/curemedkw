# Shipa authenticated manual booking runtime

This source checkpoint connects the existing review/intent SQL, canonical binding, credential loader and one-attempt dispatcher to the actual `shipa-admin` handler. It is not an application deployment, provider booking, automatic worker, tracking/reconciliation runtime, or complete Shipa acceptance. Ministry hold, shared trusted payment ownership and concrete release/live-operation gates remain unchanged.

## Administrator actions

The existing five configuration actions remain. Three additional POST shapes are accepted:

| Action | Exact body |
| --- | --- |
| `shipment.preview` | `{action:'shipment.preview',orderId,request:{environment,overrides?}}` |
| `shipment.read` | `{action:'shipment.read',shipmentId}` |
| `shipment.create` | `{action:'shipment.create',orderId,request:<strict manual review request>}` |

The manual request reuses the existing review parser: `environment`, optional `overrides`, `expectedSettingsRevision`, `expectedInputFingerprint`, `reviewReason`, `acknowledgePricing`, and `packedConfirmed`. Unknown top-level/nested fields are refused. Browser actor, paid status, credential, endpoint, integration identity or execution budget is never authority. Existing method/preflight/body-size/CORS behavior is retained. Each POST verifies `auth.getUser` and a real `user_roles(admin)` row before action work. Headers/query actor claims cannot replace the verified actor, and SQL independently checks that actor.

Preview is diagnostic, not dispatch permission. Targeted `shipment.read` calls `shipa_read_shipment`, which is **mutating** because it can expire an elapsed submission lease to unknown. It is not a read-only operational probe and never grants retry authority. Both operations need no encryption key or provider call.

Create performs exactly one `shipa_request_manual`, one `shipa_resolve_dispatch_binding`, lazy keyring load, then the actual dispatcher. The canonical lookup must return exactly four snake-case fields: `shipment_id`, `order_id`, `integration_id`, `environment`. Its shipment, reviewed order and environment must match, and the integration must be a UUID. No key or provider work occurs on missing/malformed/mismatched binding. The real loaded credential revision/fingerprint, frozen payload, token and received-lease checks remain mandatory; begin-submission stays the sole creation authority. There is no default integration, browser-selected dispatch binding, second review, provider lookup, retry or fallback provider.

## Budget and cancellation

One server-owned monotonic admission budget of at most 15000 ms starts before the manual review operation and is shared through canonical lookup, key loading, credential read/decrypt, preparation and durable begin. Standalone dispatcher invocations receive a fresh budget per invocation. Each pre-dispatch lazy operation checks the budget before it starts; its await is bounded by remaining time. A late pre-dispatch answer is refused even if the event loop has not run its overdue timer callback. A backward clock cannot restore consumed time. Request cancellation is passed into a **per-request** manual service; an already-aborted request cannot start review, and cancellation during an uncertain review/begin prevents any late canonical/key/provider continuation.

Immediately before provider invocation, require a live admission budget with more than 3000 ms left. Reserve that 3000 ms for settlement; the provider request/body deadline is `min(10000, floor(remaining - 3000))`. After the one provider invocation, the real adapter owns its bounded fetch/body await independently of the browser signal. An observed provider result is not discarded because the browser disconnected or the admission clock expired. It receives exactly one completion RPC under a separate, fresh 3000 ms fence with the original attempt token. This settlement fence authorizes no provider operation. Normal execution reserves settlement inside the 15000 ms window; after an overdue event-loop turn, settlement may add up to 3000 ms to that window. No finite wall-clock guarantee is claimed while the process/event loop is suspended. A future scheduler must reserve this tail within its own parent envelope; the current optional admission parent cap alone is not a settlement cap. This checkpoint does not implement that scheduler or claim a 50000 ms authenticated HTTP envelope. Item timing begins after the existing authentication/body-validation path.

The existing SQL 45000 ms lease and independent wall-clock received-lease check remain; they are not replaced by the monotonic budget. There is no lease extension or new attempt. If the result cannot be persisted within the settlement fence, report `persistence_uncertain`; durable marker/unknown reconciliation remains required. The fix guarantees one persistence attempt for an observed acceptance, not successful persistence during a database outage or process death.

Fencing does not cancel backend SQL or prove rollback. An abandoned review/begin/completion may still commit. A provider request already in flight may complete after the caller disconnects; the original invocation observes its adapter result and attempts completion once. No abandoned pre-dispatch continuation is allowed to create a later booking; no completion is replayed and no outcome is inferred. Targeted reload and the permanent marker/unknown/reconciliation contracts handle remaining uncertainty.

## Results and errors

Create success uses `{success:true,data:{shipment,dispatch}}`. `shipment` is the safe **review-stage** summary; `dispatch` reports the later execution result and, when available, its authoritative persisted `summary`. A UI must not display the review-stage queued state as the final state when dispatch supplies a later summary. A `not_started` dispatch (including `credential_missing`) can return HTTP 200 because the manual intent was recorded: it explicitly does **not** mean a shipment was booked. Do not hide or retry that result. Read the canonical shipment to refresh state.

After a confirmed manual intent, canonical-lookup or keyring budget expiry returns that recorded review-stage shipment plus `not_started/budget_exhausted`; no dispatcher/begin/provider is invoked, including after the abandoned read/key promise later resolves. A lost manual review answer remains HTTP 503 `operation_uncertain` and requires reload because the intent itself may have committed.

Dispatch budget refusal **before the lazy begin is actually invoked** is `not_started/budget_exhausted`. An invoked begin with a lost/late/unusable answer remains `uncertain/begin_uncertain`; a precheck alone never proves non-invocation. After begin, insufficient admission/reserve means uncertainty and zero provider/completion calls. After provider invocation, the original outcome gets one bounded completion attempt even after abort/deadline. Lost/late completion is `persistence_uncertain`, never a resend. SQL unknown/created/possible-dispatch refusal cannot acquire another creation authority.

Shipment HTTP failures use fixed messages: `invalid_request` 400, `forbidden` 403, `not_found` 404, `conflict`/`not_eligible`/`needs_reconciliation` 409, `invalid_response` 502, and `upgrade_required`/`unavailable`/`operation_uncertain` 503. Existing configuration failure vocabulary remains separate. No draft, raw provider/SQL error, credential/ciphertext/nonce, payload hash or attempt token is returned.

Once the strict `shipa_request_manual` acknowledgement confirms an intent, every subsequent error response retains those same status/code/message semantics and adds `error.intent: {id, state}`. `id` is the SQL-owned shipment intent row ID (there is no invented second intent UUID); `state` is its acknowledgement-stage state, not a claim about a later final dispatch outcome. The receipt grants no retry authority. This includes missing/invalid master-key configuration and canonical lookup/binding failures; a malformed or foreign **post-intent** binding still returns its original 502/409 with the confirmed receipt. A malformed/foreign request rejected **before** any confirmed intent has no receipt. A lost/unusable manual acknowledgement may have committed SQL but supplies no trustworthy identity: retain `operation_uncertain`, no invented receipt or new lookup/retry. Browser/upstream error receipt-like properties are not authority. A confirmed intent does not turn every failure into HTTP200.

A budget refusal before the lazy manual review callback is actually invoked is HTTP503 `unavailable`, with zero review RPC and no receipt; an invoked/lost review remains `operation_uncertain`. Promise rejection and synchronous throw are subject to the same monotonic deadline/abort check as successful settlement; live errors retain their original identity. An already-started rejected promise is observed even if admission expires during invocation, preventing an unhandled rejection without adding a late work continuation. Provider-window admission floors `remaining - 3000` first and refuses values below one millisecond; a fractional window is never promoted to a millisecond at the expense of settlement reserve.

SA rejected the round-two suggestion to detach cancellation around durable begin. The approved pre-dispatch fence above remains: an aborted/late begin never authorizes a later provider call or resend, and local absence never becomes durable retry authority. No cancellation policy, lease, SQL state transition or native operation was changed by the final bounded corrections. Bot cap remains two rounds; a new source head goes to SA's exact-head source gate, with no third bot request.

## Validation provenance

Manager-run frozen Deno 2.5.6 tests cover 388 Shipa cases, including both explicitly registered admin test files; check/lint/format passed. New failed-before-fix regressions demonstrated that request cancellation was not wired, backward time could restore a budget, and a late answer could beat its timer. The corrected code also has a partial-time test: 8000 ms spent in review plus 8000 ms in credential loading cannot reset the core's budget or reach begin/provider.

`submission_service_proof.py` runs the actual handler, SDK, auth-role helper, stores, native crypto and actual `service_role` SQL against the guarded disposable database. Its remote auth response and provider POST are synthetic. Actual SQL role lookup is used; an observer-only fixture-owner query proves a durable submission marker exists before each synthetic provider POST. The manual HTTP path books once, reloads created state and refuses replay with no second POST. Invalid session and forged body actor produce no dispatch RPC. Retained response-loss/unknown/one-marker cases still pass. The proof made 54 bridge operations and restored/reapplied all 19 migrations in its finally path; a final probe found release unmigrated, both integrations disabled, retention false and no shipment/marker/tracking/reconciliation/message-attempt rows.

These are manager receipts, not independent SA reruns, deployed router/PostgREST/CORS/browser proof, native Shipa entitlement/idempotency proof, or production concurrency/activation acceptance. Full worker, tracking/reconciliation services, order UI, shared payment wiring, assembled review and gated release remain unfinished.

A subsequent test expectation initially used snake-case keys for the completion payload; the actual RPC contract uses camelCase inside `_result`, and the expectation was corrected without changing that production contract.

The minimal corrections preserve one provider invocation and one same-token completion, separate admission from settlement, preserve confirmed intent on pre-dispatch read/key timeouts, and track whether the lazy begin actually ran. Seven new regressions include abort during completion and exhausted settlement reserve. Final focused validation on pinned Deno 2.5.6: 79 tests passed across the new regression file, dispatch, dispatch-budget, execution-budget and authenticated shipment-handler suites; frozen entrypoint check, changed-TypeScript lint/format and Git whitespace checks passed. Earlier full-suite and actual-SQL receipts above were not rerun or relabeled as evidence for this correction. Synthetic SDK/fetch boundaries remain; no server, native Shipa, migration, merge or deployment operation was performed.
