## Failures found and corrected

Initial SQL execution caught the order_status enum needing an explicit text cast, PL/pgSQL column/local-name ambiguity and a fixture block label qualification error. They were fixed in source/fixture, not bypassed.

The first full contention runs failed: an unconditional account `INSERT ... ON CONFLICT DO NOTHING` waited on the index tuple before reaching SKIP LOCKED and hit the peer's3-second timeout. The manager changed existing-slot claims to bypass INSERT. Missing slots use a database try-advisory bootstrap lock; a second simultaneous bootstrap refuses without waiting/granting another token. Both existing-slot and missing-slot races now run against real transactions. This is not a process-local lock or a fabricated concurrent mock.

An additional harness failure came from trying to observe another session's detailed lock metadata while still service_role (`intent_writer_did_not_contend`). The RPC mutation remains service_role; only the observer resets to the disposable fixture owner, matching retained harness practice. The error was not mistaken for a production concurrency defect or hidden as a pass.

## Contract dispositions and limits

Permanent/session/validation failures and exhausted safe attempts go to needs_review, following the approved WhatsApp specification. The old unintegrated pure policy's exhausted=>failed branch is a known integration correction, not the chosen SQL behavior. Current provider adapters do not attest the new generic proven retryable class; their429/5xx/unknown effects stay uncertain. Safe retry mechanics here use synthetic service attestations and establish no new provider guarantee.

Paid legacy uses its immutable legacy outcome and current canonical audience switches without GET/automation/heartbeat. Unknown legacy accounts stay unresolved. Request-backed shipped/old-shape event identity, pre-migration facade/baseline rollback and activation sequencing remain required. Manual/test ignore automation/heartbeat but honor the integration pause and require an existing admin-attributed request; the authenticated enqueue endpoint remains unfinished. Expiry/claim are mutating, never read-only probes. A cancellation after claim cannot recall an in-flight send.

Next dependent gates remain: runtime decrypt/strict response parsing/no-HTTP-before-commit/budgets, message enqueue and shared facade, acknowledgment and message mapping, explicit audited retry/requeue/duplicate-risk consent, connection/webhook/media/history/inbox/full donor parity, real scheduler and operating status, payment handler/sweep/protected-writer/retention activation, admin UI, final assembled suite/Astra review and approved production schema/app deployment/rollback/native proofs. All Ministry hold, unchanged pricing/email, separate production migration/merge/pairing/customer-message/live-payment gates remain. No completion or acceptance of either full integration is asserted.
